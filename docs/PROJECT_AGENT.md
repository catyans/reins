# Public project update Agent

Reins now includes a finite, local project-update workflow with durable requests,
conservative source dependencies, separate quality evaluation and a read-only page.
It demonstrates maintaining public project profiles across real release snapshots.

## Run locally

```bash
python -m pip install -e '.[dev]'
PYTHONPATH=src python benchmarks/project_sources.py
PYTHONPATH=src python benchmarks/project_experiment.py --key-file /path/to/gemini.env
PYTHONPATH=src python benchmarks/project_recovery.py --key-file /path/to/gemini.env
PYTHONPATH=src:benchmarks python benchmarks/project_diagnostics.py
python benchmarks/render_project_report.py
python -m http.server 8788 --bind 127.0.0.1 --directory website
```

Open `http://127.0.0.1:8788/projects.html`. The page only fetches static JSON; opening
multiple browser sessions does not dispatch model calls. These commands do not
deploy a server, change nginx or install a recurring schedule. PDF rendering needs
the optional `reportlab` package.

The collector freezes 60 projects, split 20/20/20 by organization, before any model
outputs exist. Three distinct README release snapshots per project are pinned to
commits. LICENSE and changelog files are included when available. Source-fetch
failures and exclusion reasons are saved. Sources are selected from a fixed list,
then ordered by project hash; results do not affect selection.

## Operator commands

```bash
reins projects run --dataset output/benchmarks/projects-v2/dataset.json \
  --output output/project-operator --key-file /path/to/gemini.env \
  --policy incremental --split development --budget 30 \
  --public-output website/project-status.json

reins projects resume --dataset output/benchmarks/projects-v2/dataset.json \
  --output output/project-operator --key-file /path/to/gemini.env \
  --policy incremental --split development --budget 30

reins projects status --output output/project-operator
reins projects export --output output/project-operator \
  --destination website/project-status.json
```

Use the same dataset, output directory and policy when resuming. Completed jobs
are idempotent. `resume` does not authorize a retry of an uncertain provider request.
Credentials are read from the environment or a local file, never copied into public
artifacts. The packaged runner accepts a frozen source dataset; collection is the
separate benchmark command above, not a general browser crawler.

## Execution and recovery

- SQLite WAL stores jobs, request reservations, actual token-cost estimates and
  events. A filesystem lock enforces one writer; task concurrency is four.
- Reins `trace`, `step`, outcome tracking and `CheckpointStore` remain in use. The
  worker owns its DuckDB connection; the public page never queries it directly.
- Each model request has a durable key covering job, model, purpose and prompt.
  A completed response is reused after a crash, including a crash before the
  enclosing field checkpoint commits.
- A source or extraction-version change invalidates its dependent checkpoints.
  Prompt compaction does **not** shrink the dependency: a new README section still
  causes re-extraction. There is no unverified semantic-cache hit.
- Rules handle clear installation commands and license identifiers. Remaining
  fields use Flash Lite, with Flash and full context for missing/unsupported output.
- Provider timeouts and ambiguous failures keep their budget reservation and hold
  the task. No implicit provider retries or external-action replay occurs.
- Writes are local and idempotent. This is not a distributed queue, exactly-once
  external transaction system or autonomous account reconciliation service.

Status exports use explicit public fields and atomic file replacement. A completed
run remains completed; an old heartbeat is shown as saved state rather than live
execution. Detailed provider responses, prompts and databases stay outside `website/`.

## Comparison and quality

The experiment retains a zero-model parser, fixed Flash Lite, fixed Flash, a
parser/model/whole-step-cache baseline and the incremental candidate. Every arm
uses the same snapshots and concurrency limit. Policy order rotates deterministically.

References are generated by Flash **before** strategy evaluation, checked for exact
source support and saved. They are model-assisted labels, not human gold. A separate
Flash call evaluates candidate factual completeness against original source documents,
with policy names and costs hidden. This evaluator is from the same model family and
can share its biases. Acceptance requires both valid provenance and this evaluator's
approval of every field. It is not a human-blind quality guarantee.

The cheapest baseline meeting 95% observed validation acceptance is frozen before
test. All test arms are reported, regardless of whether savings are supported.
The pilot has 20 held-out projects, not 80 independent customers: four phases per
project include correlated history and an unchanged repeat. Existing production
promotion thresholds are not relaxed and no policy is automatically deployed.

Processing latency includes runtime extraction, validation and persistence on
frozen snapshots. It excludes original network acquisition and separate evaluator
latency; it is not a measured live crawl SLA. API estimates use actual input,
cached-input and completion counts at standard Gemini text prices. Research labeling,
evaluation and recovery usage are reported separately. Local CPU time is not priced
as an invented cloud bill. Pricing reference: https://ai.google.dev/gemini-api/docs/pricing.

## Evidence and product positioning

`output/benchmarks/projects-v2/` contains source snapshots, the frozen protocol,
reference manifest, durable request logs, evaluation judgments, test results and
the isolated recovery report. `output/pdf/reins-project-update-report.pdf` is the
readable report; the website copy is the same PDF.

AWS AgentCore already supports tracing, evaluation, model-independent execution,
prompt/tool-description optimization and controlled A/B testing. Reins focuses this
pilot on source-aware data updates, durable reuse and cost per accepted deliverable.
Cross-model support or a dashboard alone is not an exclusive advantage. This run
does not benchmark an AWS deployment or establish superiority over AWS.

## Recorded pilot and reliability hardening

The September 30 pilot completed 1,172 of 1,200 execution tasks. Twenty-eight tasks
remain held; nine execution requests and eighteen evaluator requests did not return
confirmable usage. Their reservations remain recorded. Completed work was preserved,
and the recovery fixture reused the interrupted response without another request.
The comparison does not establish quality-equivalent cost savings.

`project_diagnostics.py` is an offline audit: it identifies literal citation failures
that may be formatting differences and disagreements on identical answers. It does
not alter labels, acceptance decisions or frozen policy selection. The measurements
retain the original extraction behavior. Following the audit, the runtime was hardened
so source-invalid checkpoints are rejected instead of being reused; this guard is
covered by regression tests, not claimed as a newly measured cost improvement.

To inspect a provider incident, use `status` and the private request ledger first.
`resume --acknowledge-circuit "operator reason"` permits new work after inspection.
It does not settle previous charges or resend uncertain requests. A consecutive-failure
circuit stops dispatch after three unresolved calls without an intervening success.
The ordinary `resume` path never overrides that circuit. New extraction tasks and
source changes remain subject to the existing budget, including unresolved reservations.

## Grouped update regression

`--policy grouped-incremental` adds a conservative alternative to the original
field-by-field Lite/Flash cascade. It loads the last completed project record,
checks each field against the hashes of its **full** source dependencies, and
reuses only fields that still pass exact source validation. All remaining fields
share one Flash request, without speculative repairs. A newly added or removed
source invalidates dependent fields. Existing policies and measurements remain
unchanged; the original default experiment still uses its original five policies.

`--policy cached-flash` is the matching full-document Flash cache control. It
separates ordinary repeat caching from any additional field-level reuse benefit.

```bash
PYTHONPATH=src:benchmarks python benchmarks/project_grouped_experiment.py \
  --key-file /path/to/gemini.env
```

This finite comparison writes to `output/benchmarks/projects-grouped-v1/`, never
to the website. It freezes source/runtime hashes before execution and reports
all three arms, including missing work, unchanged rechecks, cost per accepted
result and the original independent quality evaluation. Because the dataset was
already examined, this is a regression comparison, not fresh unseen validation.
Uncertain requests remain held with reserved costs; do not delete or retry them
to make the comparison appear complete. Local execution does not deploy a server.

### September 30 grouped regression result

The 20-project replay compared 80 tasks per policy with Gemini Flash throughout.
Recorded workload API estimates were $0.33103329 for full refresh (51 accepted,
77 assessed; one execution request has unknown cost), $0.26447357 for whole-document
cache (54 accepted, 73 assessed), and $0.25558092 for grouped updates (50 accepted,
78 assessed). Every planned task remains in the denominator. The cached and grouped
arms have complete execution-cost records; judging remains incomplete for some tasks.

The present recommendation is **`cached-flash`**, with at least **20.1% less workload
API spend than full refresh's known spend**, while already having 54 accepted outputs.
Even assigning all three unassessed full-refresh tasks a success produces at most 54.
This is a conservative comparison within this regression, not proof of general quality
equivalence. Selection was retrospective; no policy passes the 95% production quality
threshold. Grouped updates did not improve cost per accepted result over ordinary
caching and should not replace it by default. Existing online results are unchanged.

```bash
reins projects run --dataset output/benchmarks/projects-v2/dataset.json \
  --output output/project-cached-flash --key-file /path/to/gemini.env \
  --policy cached-flash --split validation --budget 15
```

The readable local result is `output/benchmarks/projects-grouped-v1/report.html`.
Raw reports, usage ledgers, source dependencies, the frozen extraction source and
individual quality judgments remain in that directory. New source-code versions
require a new output directory; a hash mismatch must not silently mix experiments.

## Offline quality calibration and narrower workloads

`benchmarks/project_quality_calibration.py` keeps the original outcomes and adds
an explicitly different **source-backed summary** contract. Purpose and release
notes may be paraphrases when the independent factual evaluator approves them and
their quote matches the source, allowing whitespace differences in prose. No words,
negation, punctuation, code identifiers or command arguments are removed. Installation
commands and license fields retain the original strict validator. Missing evaluations
remain unaccepted. This contract is offline only; cached runtime acceptance has not
been weakened. The 95% production threshold is unchanged.

On the existing 80-task regression, original / summary acceptance is 51 / 65 for
full refresh, 54 / 64 for document cache, and 50 / 63 for grouped updates. These are
post-hoc **task-contract changes**, not improved model outputs or a fresh validation.
They do not establish equal quality or production readiness. The 20.1% regression
recommendation above uses the original contract only, not the recalibrated one.

Two narrower workflows merit separate validation:

- Installation metadata: the grouped arm has 77/80 strictly correct, source-backed
  installation fields (96.25%). This is a field-level finding from a four-field
  workflow, not a standalone agent acceptance or cost result. Validate documented
  commands; do not execute untrusted README commands automatically.
- License inventory updates: 78/80 snapshots contain a license file, and 50/60
  subsequent updates have the same license-file hash. That suggests an opportunity
  to skip repeated extraction. Missing documents remain review tasks. A stable hash
  does not establish legal compliance, accuracy of a classifier or 83% total savings.

No additional Gemini calls or server changes are used for this calibration. The
artifact `quality-calibration.json` retains every changed judgment and source link.
