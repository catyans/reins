One model. The same 100 audit documents. Reins selected a compact, 16-item batch policy on a separate validation set, then checked it against the same five-field acceptance test.

100/100Accepted in this audit

Compared with single-item Gemini 2.5 Flash-Lite execution. Both policies received the same source-based arithmetic tool; fallback calls are included.

Already batching? We tested that too.

Against compact four-item batching, the selected policy delivered 11% lower cost and 2.0× throughput, with 100/100 accepted for both. This stronger baseline was added after selection; the winner was not reselected.

The tradeoff: p95 batch service time increased from 2.36s to 5.79s against compact four-item batches (2.48s for single-item execution). This configuration fits offline jobs; it is not a real-time latency improvement.

Token costs use standard API list prices, not billing debits. One constructed workload with shared templates; measured sequential job throughput, not concurrent serving capacity or customer ROI.
